# Agent questions (`ask_user`)

Every agent in OpenOrc can ask you questions with `ask_user`, a tool on OpenOrc's private MCP connection for that run. Questions appear as a question card in the conversation, in the inbox, and as a notification. Claude Code and Codex also have their own question tools, which OpenOrc shows as the same card.

## The tool

`ask_user` takes 1 to 10 questions. Each has a unique `id` and a `question`, and can have a `header`, up to 30 `options` (`{label, description?}`), `multiSelect`, and `allowOther` (a custom answer, on by default). A question without options shows a text field. Duplicate IDs or option labels, empty questions, and reserved names are rejected before the question is shown.

The result carries a `requestId` generated by OpenOrc and is either:

```json
{ "status": "answered", "requestId": "ask-user-…", "answers": { "color": ["Blue"], "features": ["Search", "Export"], "note": ["Ship next week"] } }
```

or `{"status":"cancelled","requestId":"ask-user-…"}`. The same result is returned as text and as `structuredContent`.

## When questions can be asked and answered

- Questions are accepted only during an active turn. After a turn is stopped, the agent cannot ask again until you send a new message.
- Autonomous mode never answers for you; the question waits for your reply.
- Your answers are checked against the questions still waiting before they are used, and an old reply cannot answer a newer question.
- Declining, interrupting, the agent exiting, the turn or run ending, closing the app, or the MCP connection dropping all end the question, and the card shows how it ended.
- OpenOrc sets no time limit on a question.

## OpenCode

OpenCode's own question tool does not work through the connection OpenOrc uses (ACP), so OpenOrc turns it off and points OpenCode at `ask_user` instead:

- Every OpenCode prompt names OpenOrc's MCP server and how to reach `ask_user`, including through Code Mode search at `tools.<server>.ask_user`.
- OpenCode is started with an `OPENCODE_CONFIG_CONTENT` override that denies its `question` permission globally and for the `build` and `plan` agents, plus any custom agents defined in the inherited inline configuration. Your existing JSON or JSONC configuration is kept, and your other permissions are unchanged. No installed file or global setting is edited.

OpenCode applies permission rules in order, with agent rules after global ones. Custom agents defined in project files, saved session rules, or plugins can still re-enable the native question tool, because ACP offers no session-level permission override. The prompt guidance helps but cannot enforce this. See [OpenCode permissions](https://opencode.ai/v2/docs/permissions) and [tools](https://opencode.ai/v2/docs/tools). This configuration targets OpenCode 2.

A running OpenCode process keeps the configuration it started with. Start a new conversation, or close and reopen the agent process, to pick up changes.
