# Interface conventions

OpenOrc uses a neutral desktop shell, compact navigation, and spacious reading and editing columns. Shared components and semantic tokens keep conversations, task documents, and review panels consistent.

## Tokens and appearance

Color palettes are defined in `apps/desktop/src/renderer/src/lib/theme-palettes.ts` and applied by `lib/theme.ts`. Components use semantic variables from `app.css`: `--surface` for the conversation canvas, `--bg` for the sidebar, `--paper` for inset work panels, `--composer-input` for writing areas, `--ink` roles for text, and separate action, link, border, and status roles. OpenOrc uses neutral gray/white or charcoal grounds with blue accents. Cursor shares the geometry with monochrome accents. Other dark presets may set `--surface-gradient`, an image painted over `--surface` on the work plane. Light planes stay flat. Sticky headers that must blend into the plane use `well-fill`. Light, dark, and system appearance are independent of palette selection. Verify both appearance modes and saved custom colors when changing a component. The app-scoped [design record](../apps/desktop/DESIGN.md) records the built system and its tokens.

Typography and radii use the shared `@theme static` tokens in `app.css` with workspace rules in `workspace-design.css`. System sans-serif is the default throughout the app, including task and welcome headings; Cursor uses Inter Variable. Code uses JetBrains Mono with platform monospace fallbacks. Thread titles use 13px semibold type in the top toolbar. Conversation prose is 14px at 1.6 line height, composers use 13px text, and ordinary controls use the 13px base or 12px small role. The flat composer has an 11px shell and 8px writing area; bordered user prompts use 12px corners, and inset work panels use 14px corners. Assistant responses stay unboxed. Thread titles and contextual tools share the top toolbar. Team revision details, activity visibility, and context compaction live in its team menu; named agents get one author line rather than a repeated Assistant label. Long prose wraps; code and tables may scroll within their own containers.

One resizable sidebar holds app destinations and Threads/Orclings tabs. Threads shows Workspace and all imported projects in expandable groups with per-project new-thread actions. Rows use single-line 13px titles and a flat navigation-accent selection tint; branch and provider details remain in accessible labels and hover text. Loaded-title filtering, pinned/archived views, pagination, collapsed sections, and thread context menus remain available. Project options reserve a fixed 24px slot so hover does not move the adjacent plus button. The resize grip sits on the seam with the workspace.

Imported projects use this icon priority: explicit choice, repository image, detected framework, detected language, outline folder. Workspace retains its globe. Click a project icon to select a discovered image, choose a local file, refresh candidates, or return to the folder. Discovery is a bounded local scan on first display, with positive and negative results stored under the app's `project-icons` data folder. It does not poll, watch repositories, execute project configuration, or call a network/model service. Manual selections survive refreshes; Automatic resumes discovery. Raster previews are at most 64px; small static SVGs stay vector images.

Framework/language fallbacks are 24 upstream Devicon brand SVGs shared through `ProjectStackIcon`: React, Next.js, NestJS, Vue, Nuxt, Svelte, Astro, Angular, Express, Laravel, Django, FastAPI, JavaScript, TypeScript, Python, Go, Rust, Java, C#, Ruby, PHP, Swift, C, and C++. These are an explicit exception to the app's original outline icon policy. Preserve the upstream shapes and colors; monochrome Express/Rust invert for dark appearance, while Astro/Django retain their colors on a light ground. Detection reads at most 256 root entries and five metadata files (64KB each); it does not walk source trees or dependency directories. It prefers specific frameworks over their dependencies, and leaves workspace roots or ambiguous stacks on the folder fallback. Plain projects can use root source extensions as a language hint. These logos ship once with the app; each project caches only an ID or a negative result. Refresh updates detection. Version-3 caches upgrade older automatic results once and preserve explicit choices.

The optional **Transparent surroundings** setting uses native blur on supported systems. Its **Transparency** slider ranges from 0% (solid palette tint) to 100% (native blur without a palette tint), defaulting to 35%. `.app-shell` paints this tint once behind the sidebar and surrounding window chrome through `--shell-opacity`; keep the main work planes, tool content, and expanded panels opaque. The saved level survives toggling transparency off and on. Preserve `--bg` as a solid palette color so gradients, previews, and custom colors continue to work. System Reduce Transparency takes precedence over the saved preference.

Appearance separates action, navigation, and content accents while preserving semantic status colors. Use `--accent` and its text/tint companions for primary actions, `--navigation-ink`/`--navigation-soft` for selected destinations and filters, and `--content-ink`/`--content-soft` for reading accents. Each palette defines its own defaults: Claude keeps ink controls, clay navigation, and blue links; GitHub uses green primary actions and blue navigation and links, following [Primer's color roles](https://primer.style/product/getting-started/foundations/color-usage/); Eliron keeps graphite controls, pink navigation, and blue links. Other palettes retain their signature hue with separate fill and readable-text values. Accent combinations and custom role colors are stored per palette and light/dark mode. Unset roles use the selected palette's defaults. Editing or resetting Actions leaves Content and its selection color intact; resetting all accents preserves unrelated overrides. Text and tints adapt to the selected hues; advanced token overrides remain available.

Persistent UI surfaces use flat fills, typography, spacing, and fine borders instead of raised material shadows. App-scoped material overrides include selected rows, composers, cards, and inset controls. Floating menus and temporary overlays retain depth so their boundaries remain clear.

The sidebar uses its own neutral ground and a fine seam with the workspace. Main and panel toolbars use the canvas ground without bottom header dividers. Transparent surroundings paints the shared frame once; reading planes and inset tool content remain opaque below their headers.

## Layout and controls

Repository headings offer **Remove project** through right-click or the options button. Removal only hides the repository from project lists and pickers: files, worktrees, history, running work, and schedules are retained. Importing it again restores the same project. Workspace cannot be removed.

The sidebar defaults to 267px and appears across destinations; existing saved widths remain authoritative. There is no separate icon rail. New thread, Tasks, Schedules, and More sit above the conversation tabs; Add project, Settings, Inbox, and history sit in the footer. When navigation is hidden, the main toolbar retains navigation and search controls. Toolbars are 40px at normal zoom and preserve native window-control clearance when zoom changes. Conversations use an editable toolbar title, bounded user prompts, unboxed replies, and an optional tabbed work panel for changes, files, terminal, browser, and other tools. The panel defaults to 640px, respects saved widths, and has 12px side/bottom insets. Each column owns its scrolling. Resize handles support keyboard input, dragging, and reset.

At viewport widths of 900px or less, navigation overlays the page and dismisses when a conversation or destination opens. At work-row widths of 788px or less, an open panel overlays the work area instead of squeezing the conversation; panel expansion remains independent. Project scope controls Tasks and new threads without hiding other projects from the browser. Opening a thread keeps the multi-project list available, and Command-click or Control-click opens a split pane.

Use the existing button, input, menu, dialog, and segmented-control primitives. Generic segmented selection uses text emphasis on a transparent background; task filters have separate padded targets and a soft selected fill. The composer pairs a raised neutral shell with a distinct writing area. Mode and model controls rest on transparent backgrounds, model and effort stay together, and controls wrap onto a second row at composer widths of 440px or less. Git changes stay inside the composer, with the branch displayed once and the working-folder path below. Clicking context usage opens details; compaction requires its explicit action. An empty running composer shows Stop; text or attachments restore Send with a separate Stop control. The effort knob stays white and its fill ends at the thumb center. Task creation and starting execution are separate actions, drafts survive navigation, and save states reflect acknowledged persistence.

Recurring actions in task lists, schedules, and team toolbars use neutral icon buttons with accessible names and tooltips. Keep text buttons for form submissions, empty states, and decisions that need an explicit label. Reserve strong color for status, diff meaning, and destructive feedback rather than routine action fills.

Agent updates live in Settings → Connections: each agent shows its installed version and any available latest version, with explicit Update and Update all actions, a manual check, and an automatic-check toggle. Reuse shared buttons, badges, toggles, and Precision Outline icons; let agent rows and toolbars wrap at narrow widths. A dismissible notice in the upper-right workspace uses the same surface and text tokens, with Review updates leading to Connections so versions and update results stay together.

OpenOrc release updates share that upper-right notice stack, above agent updates. Use the existing Download icon, neutral surface and text tokens, and explicit Download update, Later, and Restart to update text actions. Progress uses a labeled native progress element with a percentage; failures and restart refusals remain readable in the notice. Notices wrap within the window and scroll as a stack on short windows, without overlapping each other. Later is remembered per version across windows and restarts. The notice covers the native Preview while visible so its actions remain reachable; downloads and failed installs have a Hide action to restore Preview access. A hidden download notice returns when ready.

Responsive behavior follows available column width. Allow properties and toolbars to wrap; secondary labels may yield while accessible names remain. Check narrow windows, split conversations, enlarged text, keyboard focus, and reduced motion.

## Icons and motion

The [Precision Outline family](precision-outline-icons.md) uses original Codex-generated geometry on a 24-unit grid, 1.75-unit strokes, rounded caps and joins, and `currentColor`. Reuse the shared components rather than adding another icon library. Controls retain accessible labels. Filled collaboration status marks and the original Hollow conversation indicator are deliberate exceptions to the outline family.

Generic agent presence uses a flat, single-color face. Individual Orcling artwork retains its shapes, colors, and personalization. Threads and Orclings share the sidebar through tabs and keep their last selected conversations; switching tabs in compact navigation keeps the list open. Companion home chats stay out of project thread lists, and private instructions and memory remain separate from Workspace and project memory. Production routes use real companions and their existing chat, profile, and designer. The standalone design preview uses synthetic providers, sample companions, and session-only settings; it does not exercise live provider actions or Orcling services. Navigation visibility remains configurable under More → Edit sidebar.

Motion communicates state through short transitions. Respect reduced-motion preferences; the generic agent mark stays still when idle and uses only a restrained opacity pulse while thinking. Status meaning must remain understandable through text and shape as well as color.
