# Code quality checks

Run `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, and `pnpm test` before review. CI runs these checks before building. The desktop release workflow also runs lint and formatting on its selected source commit before packaging.

TypeScript checks unused declarations in package sources and both desktop projects. The website inherits Astro's strict configuration and explicitly enables unused checks. ESLint covers authored JavaScript and TypeScript; application TypeScript uses its actual compiler projects for promise analysis. Renderer components and disposable React fixtures also check hook rules and dependencies. Standalone TypeScript scripts and configuration use ESLint's unused-variable rule because they are outside the application compiler projects.

Generated output, dependencies, local reports, and preserved vendor notices are excluded deliberately. Astro templates are checked by Astro's typecheck; the current Prettier setup has no Astro parser, so review their markup formatting manually. ESLint does not parse `.astro` templates. The desktop Vitest configuration uses `.mts` so its ESM-only Vite dependency loads without the CommonJS warning.

## Existing lint debt

`eslint-suppressions.json` is ESLint's standard bulk-suppression format. Each entry permits only the recorded count for one rule in one file. No source file is wholly exempted. Entries are removed as the code they cover is repaired. A suppression is not a claim that the diagnostic is safe.

## Reducing the baseline

After repairing an entry, run `pnpm exec eslint . --prune-suppressions`, inspect the suppression diff, and format it with `pnpm exec prettier --write eslint-suppressions.json`. Remove entries for deleted or newly ignored files explicitly; ESLint may retain them because those files are no longer visited. Run `pnpm lint` again. Normal lint fails on newly exceeding a recorded count and on obsolete suppressions for visited files.

Do not regenerate the baseline to make a failing change green. New entries or increases need a specific review explanation and a follow-up owner. Counts are per file and rule, not source-location fingerprints: replacing one old violation with one new violation can fit the same count. Review the full diagnostic output when changing a file that still has debt (`pnpm exec eslint path/to/file --format json --pass-on-unpruned-suppressions` includes its suppressed messages), and reduce entries when the corresponding code is repaired.

## File and function size limits

Run `pnpm check:size` before review. CI and release builds check production TypeScript/TSX under `apps/*/src` and `packages/*/src`, excluding declaration files, tests, fixtures, generated directories and benchmark/QA entries. Physical file lines include blank lines; function lines span the declaration through its closing body. Limits are 800 file lines, 100 function lines and branch complexity 15. Complexity starts at one and counts conditions, loops, catches, non-default switch cases, conditional expressions and `&&`/`||`/`??`; nested functions are measured separately.

`size-baseline.json` records actual values for existing offenders. A file or function may shrink but may not grow beyond its recorded value. New offenders fail at the thresholds. Function keys use file paths and qualified lexical names, not line numbers, so unrelated line shifts do not reset allowances. Same-named sibling callbacks use deterministic ordinals; moving/renaming an offender or changing sibling identities needs an explicit reviewed baseline change, never automatic new allowance.

After a refactor, run `pnpm size:update`. It refuses any growth or new offender before writing, lowers retained values, and removes resolved/deleted entries. It never adds or increases entries. Inspect the diff and run `pnpm check:size` again. The one-time `--init` command creates a missing baseline exclusively and cannot overwrite one. Do not delete/recreate the baseline to pass a refactor. Tests for growth, new offenders, shrinking, update refusal and stable names run with `node --test scripts/size-limit.test.cjs`.
